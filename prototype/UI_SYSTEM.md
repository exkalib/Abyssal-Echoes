# ABYSS//FRAME 界面系统

`ABYSS//FRAME` 是《深渊回响》的唯一移动端 UI 语言。它从开屏坠舰、人物立绘、物品与建筑插画中提取同一套视觉 DNA：冷暗环境、磨损装甲、低亮金属、局部能源光和少量工业警示色。页面只负责信息结构和内容，不再自行发明按钮、卡片、颜色或状态样式。

## 1. 视觉原则

- 石墨黑承担背景与装甲面，钛灰与旧白表达机械结构，青色只表示能量、焦点和可交互状态。
- 琥珀只表示热能、制造和工业警示；绿色只表示生命与生态；红色只表示危险、损坏和退出；紫色只表示异常与规则外能力。页面不得因为“想有区别”而自创主题色。
- 默认组件不发光；仅选中、可执行、扫描和关键反馈允许短距离辉光。
- 面板使用硬边、小切角和局部高光，不堆叠大圆角、粗边框或整块霓虹。
- 插画是视觉主体，UI 是压在暗处的仪器层。物品、建筑和人物不得再套一层高饱和色块抢夺注意力。
- 背包、职业与技能必须有同一世界的场景纵深：分别复用现有舱室、反应堆与舰桥场景，操作层保持透明暗衬，不用整页纯色、嵌套大容器替代游戏环境。场景是表现层，不代表玩家移动或解锁新地点。职业立绘占据舞台主体，文字有局部暗衬；技能选中点亮自己的纹章，而非整块信息卡。
- 所有界面表面都使用同一套四层材料关系：深空黑背景、石墨装甲板、钛灰结构线、局部能源导轨。开屏的扫描纹理与冷雾只能作为低对比背景，不能变成每张卡片各自的特效。
- 旧白与暖钛色来自人物服装和坠毁残骸，只用于正文高亮与金属结构；锈橙只允许提示工业热源和磨损，不得发展成另一套橙色主题。
- 中文是主信息；英文代码仅作技术标签，不能抢过标题。
- 系统功能图标统一为 `24 × 24` SVG 线性图标，技能与职业纹章使用 `32 × 32` 画布。emoji 只允许暂时作为游戏物品插画，不作为返回、关闭、锁定、地图、状态等系统图标。
- 所有操作以触摸为准，不依赖 hover；主要触摸区域至少 `44 × 44px`。

### 手机单手操作补充（本轮优先）

- 场景和人物是主体，不能把游戏统一成大标题、指标格、长详情组成的后台。营地保留真实场景留白；设施、物品、技能使用实物插画或纹章阵列。
- `.thumb-sheet` 是装备、物品等明确请求完整详情时使用的手区抽屉，技能选中不使用它。轻量收起手柄 + 唯一滚动区 `.thumb-sheet-body` + 固定动作栏 `.thumb-sheet-footer`。底部明确返回，主要动作始终在手边；蒙层保留来源画面但阻止穿透，关闭恢复原焦点、选中态和滚动。
- 背包不再在候选后堆长详情；技能页是一张战技画面：招式投影、四列已学战技与三个装配槽。没有顶部分类标签，也不在后台挂载三套分类页面；自动能力与基础精通是场景边缘的独立图标入口，点击打开覆盖在战技画面上的手区浮层。
- 营地标题使用紧凑地点条；“营地设施”与用途筛选固定在列表上方，建造、出发固定在底部。探索的地图、探索、回营复用原动作搬到底部同一操作坞。NPC 操作类型在交互区下沿，不挤占人物舞台。
- 连续使用、采集、制作只更新数量、结果与可用态，动作按钮不能移动或消失。数量控制优先 ±1、±10，键盘输入承担任意批量。
- 手指进入滑动后立即取消按压；点击音和震动只随实际点击发生。安卓返回键优先关闭详情或返回来源页，不直接退出游戏。
- 此补充替代下文旧版“营地中枢状态面板 / 技能列表紧接详情 / 背包内联详情”的结构约定，不改变数值、路线、资源消耗与人物穿戴规则。

### 间距与形状

- 间距只使用 `4 / 8 / 12 / 16 / 20 / 24 / 32px`。
- 小控件圆角 `6px`，卡片 `9px`，大面板 `12px`。
- 系统按钮和接口允许左上、右下 `7px` 切角；内容卡片不用每块都切角。
- 默认边线 `1px`；选中增加一条 `2px` 青色能源轨。

### 文字层级

- 页面标题：`20px / 700`
- 区块标题：`16px / 700`
- 卡片标题：`14px / 650`
- 正文：`13px / 1.55`
- 次要信息：`11px`
- 英文代码、编号：`9–10px` 等宽字体，字距 `1.2px`
- 除纯装饰编号外，可读文字不得低于 `10px`。

## 3. 图标规范

- 图标从 `index.html` 的 SVG sprite 引用；系统功能图标使用 `viewBox="0 0 24 24"`，技能与职业纹章使用 `viewBox="0 0 32 32"`。
- 默认线宽 `1.6`，圆端点和圆连接，颜色继承 `currentColor`。
- 行内状态 `16px`、按钮 `20px`、导航 `24px`、主要入口 `28–32px`。
- 同一语义只能有一个图标；禁止在不同页面混用 emoji、字体符号和 SVG。
- 装备页的十个接口为：头部、胸甲、手部、腿甲、足部、背部、植入、模组、副手、主武器。
- 物品、建筑与人物使用各自的实物插画；尺寸由 `.ui-art-frame` 的 `compact / card / hero / portrait` 规格控制，页面不得直接给图片创造新的边框和滤镜。

## 4. 页面母版

所有页面必须先选择一种母版，不能边写业务边临时决定页面结构。

| 母版 | 统一类 | 使用场景 | 常驻 HUD | 退出方式 |
| --- | --- | --- | --- | --- |
| 主导航页 | `.ui-page` | 营地、探索、角色总览、职业、技能、背包、任务、设置 | 顶部状态 + 底部导航 | 点击当前导航或切换导航 |
| 沉浸工作区 | `.ui-workspace` | 设施、建筑管理、商店、NPC | 全部隐藏 | 固定底栏，文案为“关闭 + 当前对象名”或明确场景语句 |
| 画布工作区 | `.ui-canvas-workspace` | 世界/局部地图、科技树、基因树 | 全部隐藏 | 地图使用底部关闭；树状画布使用统一角落工具按钮 |
| 上下文弹层 | `.ui-dialog` | 物品详情、设施升级、死亡结算、确认操作 | 保留来源页 | 标题栏关闭或弹层底部确认 |

底部主导航固定为“角色 / 职业 / 技能 / 背包 / 任务”，五项等宽并排。职业页展示自己已取得的身份，技能页管理已学能力，二者都是一级成长页，进入后继续保留顶部状态与底部导航；建筑管理只从营地主页进入；科技树只从营地内已建成且在线的“科技台”进入，野外与底部主导航均不得提供快捷入口。

判断标准：用户进入后需要连续选择、查看详情或拖动画布，并且全局导航会挤压有效内容时，使用整页工作区；只补充当前对象信息、且关闭后必须回到原滚动位置时，使用上下文弹层。

### 工作区骨架

- `.ui-workspace`：唯一整页根容器，使用 `100dvh` 可用区域。
- `.ui-workspace__main`：唯一可伸缩内容区；滚动只发生在这里或它声明的独立面板内。
- `.ui-workspace__pane`：上下分屏的内容面；分隔线、背景与滚动条从系统继承。
- `.ui-workspace__footer`：固定在安全区上方的退出栏。
- `.ui-workspace__exit`：整宽退出动作。默认中性；离开危险操作或结束人物交谈时可使用危险语义色。
- 退出文案必须具体：`关闭熔炼炉`、`关闭建筑管理`、`关闭中枢商店`。禁止“关闭建筑操作”“退出界面”这类不知道会关闭什么的抽象文案。职业与技能属于一级导航页，不显示工作区关闭按钮。

### 统一内容骨架

- 手机阅读顺序统一为“当前状态 → 当前可执行操作 → 按需展开的规则”。避免英文编号、说明和同一个数值多次占据首屏；不删规则，只将解释收进原位展开区。
- `.ui-disclosure` / `.growth-guide`：共用轻量展开组件，44px 触摸行，中文标题与右侧展开指示；默认关闭，不承担必须看到的消耗、前置条件或主要操作。
- `.camp-facility-toolbar` + `.camp-home-scroll` + `.camp-home-dock`：标题与用途筛选位于滚动区外，背景不透明；设施与访客仅在内容区内部滚动，底部固定建造与出发。设施超过六个才显示用途分类，筛选不得重建卡片。营地名称条按文字自然高度排版，禁止用视口百分比制造大块空标题板。
- `.battle-operator-stack`：战斗记录和角色 HUD 相邻排列，随实际内容高度变化，不使用固定日志底距；技能名称和禁用原因必须可读。
- `.death-screen`：使用统一模块标题、两列结算指标和明确的检查点/轮回选择，不在死亡时添加新的资源规则。
- 通用页面、操作台、人物交互和剧情结果沿用 13px 正文、11px 提示、10px 最小标签；短屏减少装饰和重复说明，不通过缩小中文或按钮适配。
- 操作台保留上下分区和固定确认/关闭；人物交互以内容自适应的透明操作区覆盖立绘，只在内容溢出时内部滚动。移动地图节点仍沿用画布缩放与既有命中区域，不使用通用按钮尺寸改变坐标。

- `.ui-module-header`：页面或模块身份，包含线性图标、英文系统码、中文标题和一句说明。
- `.ui-section-header`：区块标题；英文码弱化，中文为主要阅读入口。
- `.ui-card` / `.ui-list-row`：所有信息卡和入口行的基础外观。
- `.ui-segmented`：分类切换；选中态只有一条能源轨，不把每个标签做成独立发光按钮。
- `.ui-art-frame`：所有物品、建筑和人物插画的统一容器；只允许尺寸和 `--ui-tone` 变体。
- `.ui-stat-grid` / `.ui-stat-chip`：角色、装备、配方和建筑数值共用，不为每种对象再建参数卡。
- `.beacon-loot-catalog`：信标掉落图鉴使用统一装甲面与文字令牌，默认折叠；物品图标固定 24px，名称完整换行。切层只更新详情，不重建选层框和图鉴容器；结算物品按容器宽度自动排成一或两列，禁止省略名称。

### 一级成长页

- 战技主画面只展示主动招式，默认只看已学，通过「技能图鉴」查看尚未取得的主动技能。常驻详情为当前招式身份、实际等级、当前效果与使用条件，固定动作坞保留三个装配槽和研习按钮。主战被动、生活能力在「自动能力」浮层查看，基础精通在「基础精通」浮层中选择研习；两者都不改变主画面选中的战技。
- 每个技能 ID 必须拥有自己的 `32 × 32` SVG 符号：中心主体占据画布约 70%，主动、守御、重击、相位、被动、现场和精通用统一功能色区分，轮廓本身仍必须能辨认具体技能。详情页使用对应的动态效果构型，战斗按钮与释放动效复用同一个符号。禁止多个技能长期借用通用剑、盾、战斗图标而只改名称。
- 招式投影使用已有独立技能 SVG；只有实际切换招式才播放一次短动效，装配、升级和重复点选不重播，并遵守减少动态效果设置。浮层显示已学自动能力或全部可研习精通，点图标进入该能力详情；列表内点击不写入主战技能选中状态。详情返回列表，列表关闭回到原战技画面，保留原选择、装配节点与滚动。精通等级无上限；背包手册入口直接打开对应研习详情，不恢复旧分类页。
- 职业页只展示当前主战身份：实际职业立绘、职业介绍、等级、经验、当前职业加成。同一属性的固定值和百分比合并显示，数值读取当前职业等级，不展示未取得的主战路线或持久化预览选择。底部固定三个副职业图标，未激活灰显且禁用；已激活显示实际名称与等级，点击只弹出该职业的介绍、属性、能力和晋升详情。取消顶部分类与独立生活专精页面。职业训练与转职仍由对应 NPC 提供，特殊转职仪式仅在取得资格后出现在仪式地点，保留任务、装备、材料与重构核心检查。
- 主战职业是唯一人物身份：每条正式主战路线必须提供男女两张同构全身立绘，存放在 `assets/career-portraits-v1/`，并随当前主战职业与人物外观切换。入门主战职业沿用其对应正式路线的视觉原型。
- 副职业不是人物身份，允许同时掌握多个。副职业只能以可并存的资质徽章、肩章、工具挂件或专业模块叠加在背包人物立绘周围；不能替换人物身体、主战职业立绘或当前装备层。职业页必须明确区分“主战形态”和“副职模块”。
- 真实换装目标使用男女固定姿势母版，主职决定未装备部位的默认制服，已穿装备外观优先；背部 → 基础服 → 腿/鞋 → 躯干/手 → 武器/盾 → 头具 → 接口/副职徽章依次合成。角色脸、手脚锚点和姿势必须固定。
- 每个物品必须有独立库存原画；可见穿戴还必须提供独立男女穿戴层，不能用库存图标或半透明投影冒充穿鞋、穿甲。对位、遮挡和真实 alpha 未通过验收的资源不得接入正式人物。当前正式背包已采用固定母版和逐部位装配，禁止重新接回旧职业整图加库存图标的拼贴实现。
- 背包默认展示所有持有装备，按需筛选部位。顶部分类固定，中间只有物品仓内部滚动；首次默认收起立绘，物品仓顶部“查看穿戴”可随时展开。立绘保持完整比例；收起/展开偏好随本地存档保存，穿戴和分类切换不得自动改变它。点物品只选中，不弹窗、不直接穿戴或消耗；底部固定选择条显示主要属性与相对当前装备变化，点“穿戴 / 卸下 / 使用”才执行。下一件可直接点选，操作不清掉当前选择或滚动位置。属性较多、完整对比与获取来源通过选择条明确打开单份详情，成本读取 `equipmentProgression()`，兼容条件读取 `equipmentEquipStatus()`。分类切换保留各自滚动位置与选择；材料与消耗品同样使用固定选择条，满血、库存耗尽等原因直接显示且禁用，不能盲目浪费物品。
- 五个底部标签等宽，占据各自 20% 宽度。职业、技能一级页签切换只更新面板，不重建应用；战技选择只更新投影与装配坞，图鉴仅过滤现有图标。副职业和非战斗能力详情以抽屉覆盖来源画面，关闭恢复来源界面与焦点，不改变身份、战技选择或物品。

主页面与沉浸工作区都必须有明确的视觉入口：开屏、营地、角色、背包和 NPC 由场景/立绘承担；其他页面可使用轻量模块身份，不强行堆英文码、大标题和说明。禁止用统一大标题加指标卡替代游戏主体。

### 怪物立绘与战斗背景

- 每个 `ENEMIES` ID 必须拥有一张 `1024 × 1536` 的透明全身立绘，统一放在 `assets/enemy-portraits-v1/`；新增敌人没有资产时测试必须失败。
- 怪物立绘是整张战斗页的背景主视觉，不放进头像框，也不限制在敌方半屏。使用 `object-fit: contain` 保留头、足、尾、武器与外圈结构的完整轮廓。
- 战斗页禁止再做“上半战况、下半操作”的五五分栏。固定骨架是：顶部目标捕获导轨、中央完整立绘舞台、圆形战术距离准星、贴边操作员仪表、底部内容自适应指令坞。
- 战斗界面使用独立的 `.battle-*` 组件语法；禁止用通用卡片换色，也禁止重新拼装旧 `.combatant`、`.combat-readout`、`.combat-deck`。技能槽、战术支持与主攻击核心必须具有不同轮廓和信息密度。
- 普通攻击、敌方攻击和每种主动技能都必须产生一次短暂的战斗事件动效：武器轨迹、命中扩散、技能符号和配色应能辨认动作类型。动效层不得遮挡目标生命、玩家状态或底部指令，并在 `prefers-reduced-motion: reduce` 下关闭。
- 战斗信息采用悬浮 HUD：准星不能横断画面，操作员仪表不能满宽，指令坞只占实际按钮需要的高度。可读性由局部遮罩保证，禁止通过裁掉或大面积盖住怪物解决。
- 普通敌人与首领共用同一构图和光照；首领只允许提高占屏比例、结构复杂度和警示色强度，不能另起一套 UI。
- 信标幻影等临时战斗形态复用来源物种立绘，并通过统一滤镜表达状态；不为数值变体复制近似资产。

## 5. 组件

### 面板与卡片

- `.ui-panel`：页面级装甲面，钛灰边线和顶部短能源导轨。
- `.ui-card`：普通信息或入口卡；默认不发光。
- `.is-selected`：青色边线、左侧 `2px` 能源轨。
- `.is-locked`：虚线边框、锁图标和明确条件；不能只降低透明度。

### 按钮

- `.ui-button`：默认钛灰次按钮。
- `.ui-button--primary`：青色边线、深青底；仅用于当前主要动作。
- `.ui-button--danger`：红色，仅用于不可逆操作。
- `.ui-button--ghost`：返回、关闭、地图缩放等工具操作。
- `.ui-icon-button`：视觉尺寸 `32–36px`，通过伪元素扩展到最少 `44px` 触摸区。
- 关闭控件统一为切角装甲小片：方块切角、钛灰边线、暗石墨面、`icon-close` 纯 X 图标；面板顶栏、底部弹层、科技与基因树共用同一外观，按下转青，禁止圆形或带边框装饰的变体。

按钮必须具备 `default / pressed / selected / disabled / loading` 状态。按下反馈为亮度 `1.18` 和缩放 `.97`，并可叠加可关闭的轻触震动，不依赖 hover。

### 列表、标签与输入

- `.ui-list-row`：最小高 `52px`，左图标、中信息、右状态或箭头，整行可点。
- `.ui-chip`：只承载资源数量、筛选和状态，不把普通按钮做成胶囊。
- `.ui-input`：最小高 `44px`，聚焦后边线变青并出现短能源轨。
- `.ui-tabs`：共享表面，当前项用底部 `2px` 能源线，不拆成多个发光按钮。

### 商店目录

- 商店统一使用“商路进度 → `全部 / 物资 / 装备 / 特殊` 分类 → 商品选择 → 完整详情与交易”的结构；新商人通过货架归属扩充同一目录，不另造一套商店皮肤。
- 商品解锁只读取已发现的野外地点数。锁定档位必须显示还差多少地点及下一批代表商品，不能用随机刷新掩盖成长条件。
- 装备详情必须复用 `.ui-stat-grid / .ui-stat-chip` 展示全部固定属性；材料可以不显示属性区。
- 声望只降低买价。非满声望回收价低于买价，最高声望允许同批次平价回收，但任何整数取整和批次数量下都不得出现卖价高于买价。
- 限购装备和稀有特殊物使用单件批次；“已持有”必须同时检查背包与已装备槽位。

### 设施批量操作与精通

- 回收中心复用生产工作台的数量控件，默认 `±1 / ±10`，允许输入任意批量；装备拆解的可选上限必须等于背包中的闲置数量，增量只能夹取到上限，不能先进入红色无效状态再阻止操作。
- 菌圃六类作物使用 `assets/garden-crops-v1/` 的独立作物原画；系统动作继续使用 SVG。种植物、植入材料和预计收获是三种不同语义，禁止拿收获物实物图冒充培养物图标。作物图片尺寸由统一组件限定，不得按原图尺寸撑开培养块。
- 信标选层复用 `.ui-panel / .ui-list-row / .ui-stat-grid`，异常紫只表示当前选中层。无论层数，进入挑战固定消耗一个信标电池，不消耗体力；界面预览、按钮状态与实际结算必须读取同一规则。
- 精通手册固定使用“选择精通 → 调整数量 → 确认研读”三步，不允许点击精通卡片后立即消耗。数量按钮只就地更新输入框与结果预览，不得重建弹层；批量档位包含 `+1 / +10 / +100`。
- 每项精通在 Lv100 完成基础阶段，Lv101 起解锁该精通的专属超限效果。超限等级等于 `当前等级 - 100`，每一级都必须进入实际数值公式并同步显示升级后的效果，禁止只更新描述文本。

### 反馈

- 选择配方、商品、技能、装备槽、任务页签、科技节点、基因节点或 NPC 交互类型时，只更新选中态和它控制的详情区域；再次点击当前选项必须无操作。禁止调用全局 `render()`，也禁止先清空容器再补回内容。
- 培育类设施必须让每个培养块固定拥有自己的职业技能入口，并在入口中直接显示体力消耗、推进量或不可用原因；技能结算只能原位更新对应培养块，不得刷新整张设施页面。
- 建造、升级、交易、装备等改变库存或属性的操作只更新受影响的数值、可用态与详情。背包候选列表、人物容器和滚动区须保持原节点，不能为了一个新数字整体替换工作区，再用恢复滚动位置掩盖闪烁。只有进入另一页面、结束战斗或切换游戏状态时才允许整页渲染。
- 上下文弹层的打开、切换与关闭直接增删弹层节点，不能重建来源页面。弹层关闭后，来源页的滚动、选中对象和输入数量必须保持不变。
- `.ui-progress`：轨道 `6–10px`，生命红、行动能源琥珀、研究与加载青色。
- `.ui-toast`：信息青、成功绿、警告琥珀、错误红；图标、颜色和文字同时表达。
- 普通结果、获得物品和系统确认使用底部轻提示，固定在主导航或工作区退出栏上方；只显示当前操作最重要的一条，不抢焦点、不阻断触摸。
- 警告与失败使用顶部警报条，并通过 `alert / assertive` 立即播报；不能把普通成功消息也放到顶部。
- 数值升级、建造完成等能在原控件直接看见的变化必须就地高亮；新地点、新人物和剧情推进优先使用地图标记或剧情场景；只有需要确认或不可逆的操作才使用 `.ui-dialog`。
- `.settings-media`：音效、程序化环境音乐、独立音量和触觉反馈共用设置组件；开关必须连接真实输出，禁止只改文案的假开关。
- `.settings-dashboard`：设置唯一滚动内容区，外框、标题及底部“返回游戏”固定。音量滑杆保留至少 120px 轨道及 44px 触摸高度，开关与外观切换原位更新；存档作为明确入口，版本与社群按需展开。触摸媒体规则不得重新启用外框滚动。
- `.ui-dialog`：移动端底部弹层，最高 `86dvh`，内部独立滚动。
- `.ui-skeleton`：低亮钛灰扫描，不使用卡通跳点。

## 6. 页面映射

- 营地：营地残骸场景为主体，已建设施以实物插画阵列展现；设施标题和筛选固定在列表上方，建造与出发在下方，防线从哨戒塔查看。
- 探索：中央保留迷雾与地图标记，地图、探索、回营放在下方同一操作坞；地点动作保留在内部详情，连续采集不重建按钮。
- 背包：默认所有持有装备，手机四列、较宽手机五列；顶部筛选和可选穿戴预览、固定底部选择与动作条。十个装备槽仍可筛选部位，完整对比仅在明确打开详情时显示。材料/消耗品/特殊道具保持独立分类，不强制携带人物区。
- 科技/基因：使用画布工作区；节点保持自由穿插，阶段线、依赖线和状态色遵守统一语义，不用卡通图标。科技台首次打开时按七类分支的总高度铺满视口，再允许玩家横向拖动文明阶段与手动缩放。
- 技能：一级主导航页，紧凑三分类、内部滚动纹章库、常驻选择详情、固定动作坞；三个技能栏在底部直接装卸，自动能力不显示装配，精通先调整数量再确认研读。
- 职业：一级主导航页，顶部“主战职业 / 生活专精”，单一内部滚动舞台，底部路线纹章与固定执行区；不堆所有职业档案，不弹多层详情。
- 建筑管理/商店：从场景入口进入沉浸工作区，底部统一提供具体关闭动作。
- NPC：人物立绘占据上部视觉舞台，交互区独立滚动，底栏使用符合语境的离开文案。
- 角色：人物舞台与实际核心数值，下方常驻基因、回响与战斗属性入口；回响和属性使用手区抽屉。任务/设置复用同一列表、按钮和反馈，不维护页面私有皮肤。
- 顶部状态与底部五项导航是主导航页的全局组件；职业和技能必须保留两者，沉浸与画布工作区统一隐藏，页面不得自行复制或只隐藏其中一半。
- 顶部生命与能量必须保留完整的 `当前值/上限`，时间与轮回在第一层同一行组成时间状态组，设置独占右侧，两条状态位于第二层；所有元素都在正常布局流中占位。至少支持六位数值，超长时将当前值与上限改为上下排，不能依赖绝对定位或数值缩写来避免重叠。

## 7. 移动端和无障碍

- 应用使用 `100dvh`，兼容刘海、居中挖孔和底部安全区。
- 支持 `360 / 390 / 412 / 520px` 宽度，不允许页面水平溢出。
- 所有按钮、按钮角色和表单控件统一使用 `touch-action: manipulation` 并关闭浏览器默认点击闪烁；页面不得各自实现触摸补丁。
- 所有普通操作按钮、输入框和图标按钮的实际触摸区域不得小于 `44 × 44px`。图标本身可以保持 `20–24px`，但成组图标按钮必须直接占满 `44px`，禁止用彼此重叠的透明热区凑尺寸；制作数量、分类标签、NPC 操作、地图工具和战斗指令不得例外。
- 分屏工作区、NPC 内容区和横向战斗工具栏各自使用 `overscroll-behavior: contain`，手指滑到边界时不得带动外层页面。
- 可缩放画布必须反向补偿节点命中区：缩放只改变视觉，不得把地图节点的屏幕点击范围压到 `44px` 以下。
- 地图和树状画布在手机上必须支持单指拖动与双指缩放；双指缩放围绕两指中点进行，不能只提供角落里的加减按钮。
- 全局禁止误选文字；`input` 和 `textarea` 恢复选择。
- 使用 `:focus-visible` 提供 `2px` 青色轮廓。
- `prefers-reduced-motion: reduce` 时关闭扫描、旋转和脉冲动画。
- 状态不能只用颜色表达；需要图标或文字标签。
- 详情面板、上下文弹层和分屏详情必须让内容区按文字增长；受视口限制时只允许在面板内部纵向滚动。标题、说明、效果、来源和状态文字默认允许中英文及连续编号断行，禁止以固定高度或 `overflow:hidden` 让正文越出底部背景框。

## 8. 新样式准入规则

### 人物穿戴资源规范

- 角色页和背包必须共用 `dollArt()` / `refreshDollArt()` 与同一个 `updateWearablePortrait()`，读取相同的性别、当前装备、主职和生活职业；不能另选一张职业整图当角色页立绘。职业插画只用于职业展示，默认制服不能盖掉已穿装备。
- 穿戴原画必须直接生成真正透明背景并保留原生 alpha。黑底、白底、棋盘格画进像素的生成图一律拒收，不进行本地抠图、背景移除、色键或补写 alpha 来替代，也不再就这些替代方案重复询问用户。生成失败只重试原生透明输出；若当前生成通道持续不能满足要求，如实记录能力问题并保留现有正式素材，不能把问题归为用户尚未确认透明规则。尺寸优化只允许保留比例与原生 alpha 的缩放、编码。允许将已按人体姿势制作、通过男女锚点验收的实物穿戴原画用于该物品缩略图；禁止反过来把任意斜视图标当成穿戴层。
- 透明准入必须实际解码像素：存在大面积 alpha=0 的背景，四角留白透明，不能只看 PNG 后缀、RGBA 通道名或 WebP alpha 标志。全不透明的 RGBA 仍属失败。通过后再在深浅背景查看边缘、光晕与内部残底，随后做握姿、透视和实装贴合验收；透明通过不等于美术完成。
- 每件装备提供独立穿戴资源和男女锚点；左右手、脚允许运行时独立对位，前后穿插的部件明确分层。角色脸、基础身体节点及未改的部位保持不变。
- 包肩、高领胸甲必须按男女实际体型绘制穿着态，不能拉伸空衣展示图：肩片要越过肩峰并包住上臂，脖子从真正透明的领口中穿出，后领内衬在前颈后、下缘前领在颈根前。`wornTorso` 甲片只包含盔甲，自带透明领口、弧形肩沿和腰沿；原颈部位于职业制服之上、前领之下，保留原袖子与裤靴。禁止复制矩形上身区域、携带原画袖裤或只对齐胸口中心就宣布合身。
- 合身数据统一放在 `wardrobe-fit.js`：以原画真实可见边界和男女身体接缝定位，护腿/长护臂沿对应肢体轴旋转，鞋口连接踝部。不要用库存图中心或一组通用缩放代替逐件校准。
- 完整裤装使用每件 `trousers` 的单一腰至踝原画，必须包含真实腰带、髋、裆和两条裤腿；禁止再用独立腰胯补丁与旧护腿拼成裤子。运行时可从同一原画连续映射腰、裆、膝、踝并区分后衬，膝甲保持局部等比；上下段全宽接缝一致，不能只让中心点重合。后腰在身体之后、前腰在身体之前，穿裤时只隐藏被替换的原裤与旧职业腰带，卸下精确恢复。原脸、袖、手与持物不变。
- 靴口按本件源图前沿曲线分为后壳与前帮，层级必须使用有效整数：后壳 `0` → 原人物 `1` / 制服 `2` → 裤装 `4` → 前帮 `5`。换鞋只改变裤脚在鞋帮后的遮挡边界，不缩短整条护胫或牵动膝甲；卸鞋恢复原踝长。不得用整张空鞋口压在裤腿上。
- 腿靴变更须运行 `wardrobe-trousers.test.cjs --pixels`、`wardrobe-legs.test.cjs --browser`、真实游戏穿脱及腿靴组合检查；新增鞋款补本件前沿曲线，新增裤装补完整腰裆、膝踝与后腰边界。查看同套男女腰胯、全身、靴口以及单裤/三职业；同时检查腰扣与髋机械件是否被纵向拉长。图片解码、几何契约和自动穿脱分别验证功能，不替代逐件目视贴合检查。
- v11 裤装批次的实际制作路径为内置 imagegen 原画加已告知的本地预留背景 alpha 处理，详见 `wardrobe-pants-v11-prompts.json`；不能将此批次写成“生成器原生透明且没有抠图”，也不将该批次的处理方式自动推广为后续资源的默认规则。
- v12 套装批次有用户明确授权“沿用上次本地处理，完成实装”。本批胸甲、裤甲、靴及部分背翼允许内置 imagegen 原画加预留背景透明处理，仅处理背景与抗锯齿边缘，不允许本地重绘衣甲。仍须通过实际 alpha、深浅背景和男女实装检查；原生透明与本地处理在素材清单中分别记录。本批授权不自动变成后续所有原画的默认规则。套装材质、阶段、光效和资源约束见 `../docs/equipment-visual-v12.md`。
- 全部胸甲（当前 11 件）必须设置 `wornTorso` 并提供独立男女透明资源，不能只修高级样件。轻型背心保留衣袖、肩带随肩线承重；重甲肩片包住肩峰，前领与原颈正确穿插。每件保留自己的口袋、机械结构和材质设计，不复制同一套甲。

### 通用组件规则

1. 先选页面母版，再从统一组件中组合；禁止复制已有组件 CSS 后改一个颜色或圆角。
2. 缺少组件时，先在本文件定义用途、结构、状态与变体，再在 `ui-system.css` 实现，最后由业务页面引用。
3. `ui-system.css` 是视觉令牌、基础组件、状态与兼容映射的唯一来源；`style.css` 只保留页面几何、地图坐标和内容特有布局。修改旧组件时要删掉或覆盖其旧皮肤，不能继续向 `style.css` 增加 `color / background / border / shadow` 方案。
4. 页面 JS 可以保留业务类用于定位和布局，但必须同时挂载对应的 `.ui-*` 类；业务类不得定义新的皮肤。
5. 新颜色只能加入令牌表后使用；新间距必须来自既有阶梯；新圆角必须来自既有三档。
6. `index.html` 维护唯一 SVG sprite。功能图标缺失时先补 sprite，不得用 emoji 或文字缩写代替。
7. 视觉验收至少覆盖 `360 × 640`、`390 × 844`、`412 × 915`；检查无水平溢出、主要按钮不被遮挡、可读文字不低于规范。
8. 改共享组件时至少检查：营地、探索、角色、背包、科技/基因、任务、设置，以及一个设施、一个 NPC、一个商店页面。
9. 自动测试必须验证页面母版、退出文案和共享类存在；缓存参数随 `game.js`、`style.css`、`ui-system.css` 的实际变更同步更新。
10. 新页面评审先看四件事：页面母版是否正确、标题是否来自统一入口、插画是否使用 `.ui-art-frame`、交互状态是否来自语义令牌。四项任一不满足都不能以“先做一版”为由新增私有皮肤。
### 多词条装备详情

穿戴/卸下必须保留选中物品详情、动作按钮、已展开的比较区域以及比较基准，只就地同步穿戴状态和数量；不得删除比较行、重建详情或事后恢复滚动。更换候选物品时才建立新的比较基准。

多属性装备复用 `equipmentStatsMarkup()` 与 `.rpg-equipment-stat-groups`，按输出、生存、操控与续航分组；不要在背包重新拼一大段标签文字。装备原始词条差值放进可展开的比较区，最终暴击、闪避、命中、穿透上限必须明确提示。配色来自 `--ui-line`、`--ui-text-1`、`--ui-text-2`，不为新装备发明独立皮肤。物品图统一由 `itemArtSrc()` 解析，v3 为每件扩充装备的独立透明实物图；不可用同一张图换色或复用别名补缺。
